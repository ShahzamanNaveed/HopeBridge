# HTTP conventions

A-02 (2026-10-29) implements staff authentication under `/api/v1/auth`; see [exact methods, DTOs, errors, CSRF/Origin and integration contracts](authentication.md). Earlier planned business contracts below remain requirements for their future modules, not claims that authentication is still absent.

GET /api/v1 returns a foundation/version descriptor. GET /health queries PostgreSQL; 200 means reachable, 503 means unavailable. Responses are {data: ...}. Errors are {error: {code, message, requestId}}. Every request receives a generated X-Request-ID. Unknown /api routes always return JSON rather than the SPA fallback.

Input: JSON bodies capped at 100 KB. Malformed JSON returns 400, oversized JSON 413, unknown endpoints 404 and throttled API requests 429. Production errors omit internal messages. Pagination uses page >= 1 and pageSize 1..100; domain routes must validate with shared schemas once implemented. Health is a connectivity probe, not proof that migrations or business data are correct.

## DECIDED financial transport and authorization (planned)

- **FIN-010 - DECIDED:** PKR money input/output is a decimal string backed by NUMERIC(18,2)/Prisma Decimal. At most two fractional digits; reject nonfinite, unsupported precision/range, numeric money payloads and float-derived arithmetic. Direct records never silently round; decimal-safe calculations/comparisons and explicit HALF_UP only where calculation requires it. Collections/remittances positive, adjustments signed; no FX/multi-currency API.
- **FIN-011 - DECIDED:** Authorized financial summaries distinguish scoped netRecognizedCollections, confirmedRemittances, signedOutstanding (possibly negative), reconciliationDeficit and nonnegative availableToRemit after reservations. See [measure definitions](domain-rules.md). Preserve original occurrence and recognition periods; no historical overwrite, automatic compensating payment or deficit-write-off action. External clearing/recovery/settlement remains PENDING.
- **FIN-012 - DECIDED:** Backend derives source branch from current Branch Lead assignment for cancellation requests; only Finance Reviewer may approve/reject within scope. Request does not release reservation. Decision rechecks Pending state atomically against confirmation; approved cancellation releases once with audit, rejected leaves Pending/claim intact. Confirmed cancellation and cancelled confirmation are denied. Other roles have no cancellation grant; do not expose a confirmed-remittance reversal endpoint.
- **FIN-013 - DECIDED:** Source Branch Lead adjustment request requires no other PendingReview for original; Finance decides each. Approval transaction rechecks original plus all Approved deltas/candidate >= zero, unique reference, state and exactly-once eligible recognition; prior decisions/original preserved. Rejected has zero effect, and closing request permits another.

No financial endpoints/contracts exist yet. These are required validation/role/state/concurrency behaviors, not finalized routes or completed APIs. Existing authentication/CSRF/safe-error requirements apply; attachment technical configuration and exceptional dispute policies remain PENDING; FIN-018 adjustment reason is mandatory and file optional.

API throttling currently uses per-process memory and direct client addresses. Before configuring a reverse proxy, specify and test an exact trust-proxy policy; do not blindly trust forwarded headers. Future mutation methods require validated CSRF protection and server-enforced permissions. No authentication endpoint exists yet.

## AUTH-001 to AUTH-006 behavioral contracts (DECIDED; planned)

No authentication/staff endpoints are implemented; paths and schemas remain design work. Full policies: [security](security.md). Exactly five staff roles; public visitors/members gain no staff authority.

- **AUTH-001 - DECIDED:** Backend-authorized Super Admin creation returns newly generated temporary secret only once after committed hash/issuance/+24h expiry/mandatory-change/audit controls. Response authenticated/protected, noncacheable and excluded from secret logging; no URL/storage/email disclosure or later list/detail retrieval. A lost secret requires a new authorized reset.
- **AUTH-002 - DECIDED:** Only Super Admin resets an existing allowed target; transaction replaces secure hash/expiry/mandatory-change, revokes all old target sessions and records sanitized audit. Reveal new secret once after commit, never previous password. Preserve inactive-state/last-admin/replacement restrictions; no public self-reset/email recovery grant.
- **AUTH-003 - DECIDED:** Login validates hash, active account and temporary expiry, creates new server-tracked session. Temporary login grants only minimum password replacement/session termination; successful password change securely rotates/invalidates credentials/session state before normal authorized work. Server enforces min(8h idle, 24h absolute from issuance), authorized-only idle refresh, deny at/after deadline, no absolute extension/resurrection. Logout revokes active session; current role/branch/active status checked per protected request.
- **AUTH-004 - DECIDED:** Super Admin deactivation atomically/consistently changes status, immediately invalidates target sessions and audits, subject to last-admin/lead-replacement checks. Inactive cannot login/use old cookie; activation revives no old sessions/expired temporary password and needs secure authorized credentials.
- **AUTH-005 - DECIDED:** HttpOnly opaque-session cookie with Secure production, scoped topology-appropriate SameSite/path/domain. Require CSRF token and trusted Origin for authenticated state-changing browser requests, secure deployment CORS, deny-by-default authorization, rate-limited login and generic failures. No secrets in localStorage/logs or cacheable creation/reset responses; approved hash verification, not plaintext comparison. Exact thresholds/topology/token delivery remain pending.
- **AUTH-006 - DECIDED:** Super Admin replacement rechecks candidate/single-role/assignment and Active-branch leadership in protected transaction with old/new audit. Old issued sessions lose former-branch access immediately through revocation or equivalent server invalidation; no automatic new branch grant. Rollback preserves prior assignments/access. No frontend-only security or non-revocable client JWT contract.

## WR-001 to WR-006 report behavior (DECIDED; no endpoints implemented)

Routes/schemas remain to be designed; system draft generation is not a dashboard-read side effect or new staff role. Existing authentication/CSRF/branch scope and decimal-string money contracts apply.

- **WR-001/WR-002/WR-005 - DECIDED:** Scheduled PKT Monday boundary and recovery prepare missing just-completed Active/Paused branch/week Drafts, including zero activity, idempotently/uniquely. Listing/retrieving never becomes the required generation trigger, overwrites existing state or fabricates transactions. Exclude Head Office as operational; FIN-014 ordinary Closed-branch future reports prohibited; legitimate pre-closure recognition container/period PENDING, historical reports retained.
- **WR-003 - DECIDED:** Authorized Draft/Returned retrieval returns latest eligible scoped calculation; Submitted returns preserved frozen submission revision and Approved returns immutable final snapshot. Distinguish live current balance/context from historical evidence explicitly. Submit/resubmit validates current state/version/totals and captures immutable revision/submitter/time with state/audit atomically; new resubmission preserves old revisions and locks included originals while Submitted. Return requires Finance nonempty reason; eligible correction still obeys original cutoff. No silent frozen-revision refresh.
- **WR-004 - DECIDED:** Finance approval transaction rechecks relevant unresolved issues capable of materially changing candidate eligible figures by branch/report/recognition scope. Relevant unresolved dependency denies approval without state change; unrelated branch/period/request cannot affect snapshot and does not automatically block. Never include unapproved adjustments. Reassess after resolution, preserving frozen evidence; document occurrence/recognition/candidate-report dependencies and leave exact multi-period treatment to specification.
- **WR-006 - DECIDED:** Wrong role/branch, invalid state, stale version or incompatible concurrent transition returns safe validation/conflict without partial state/revision/audit writes or internal disclosure; exact error schema/status mapping is implementation design. No duplicate successful submissions/approvals/recognition or Approved reopening. Finance approval and lock/snapshot/audit are one transaction, never separate manual Lock. Valid zero-activity reports follow same submit/Return/resubmit/approve rules.

## Shared endpoint integration conventions (future implementation)

Existing routes are GET /api/v1 (foundation descriptor) and GET /health (database probe). Future business routes use existing /api/v1 namespace, JSON where applicable and {data: ...} / {error: {code, message, requestId}} envelopes plus X-Request-ID. CSV/PDF are protected binary/text export responses, not JSON success envelopes; their errors use the shared safe error contract. No business endpoint paths, methods or schema files are generated here.

Validate params, query AND body with shared @shiplens/contracts Zod schemas; project approved fields to explicit DTOs, never serialize ORM model objects. Server rechecks current session/action/role/branch, field safety, state and domain invariants independently of client validation. Financial values canonical decimal strings under FIN-010; timestamps carry unambiguous UTC/offset instants, with Asia/Karachi defining reporting weeks/event interpretation. Backend server/DB time is authoritative. Stable public error codes drive existing i18next EN/UR messages; do not use English exception text as a durable client protocol.

| HTTP status     | Integration meaning / existing foundation distinction                                                                                                                             |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 400             | Malformed request/transport input; existing INVALID_JSON; shared Zod transport failures must be deliberately mapped, no automatic Zod middleware exists                           |
| 401             | Missing/invalid/expired/revoked protected session; not implemented authentication                                                                                                 |
| 403             | Valid identity forbidden action/scope; do not reveal private matches                                                                                                              |
| 404             | Missing/unavailable record, including concealed existence where required; existing NOT_FOUND                                                                                      |
| 409             | Duplicate/current-state/version/concurrency conflict with privacy-safe codes; no automatic retry of unsafe mutations                                                              |
| 422             | Well-formed domain-invalid request where deliberately supported/documented by endpoint contract; HttpError supports status but no automatic business/Zod mapping exists           |
| 429             | Rate limiting; existing RATE_LIMITED                                                                                                                                              |
| 413 / 500 / 503 | Preserve foundation oversized-body/internal-safe-error semantics; /health intentionally returns {data: health} with 503 for unavailable database, not the ordinary error envelope |

Before coding each endpoint, producer/consumer review concrete DTOs, stable code catalogue, field-error representation and deliberate 400/409/422 exceptions together. Current errorResponseSchema has only code/message/requestId; any structured field-error extension must change shared schema, server mapping and central client compatibly. Current apiGet casts successful envelope data and throws a string Error, so richer runtime DTO validation/localized code handling, mutation/CSRF and export download support remain unimplemented extensions. Pagination currently page >=1/pageSize1..100; domain audit filters/defaults still need a reviewed contract rather than assuming every endpoint implements it.

Protected requests use AUTH server sessions, deny-by-default action policy and backend-derived branch ownership; ID guessing/client branch filters never broaden access. Apply CSRF/Origin checks to protected unsafe forms and approved anonymous APP controls to public intake. Public CMS/branch DTOs expose only authorized published/public fields, never Draft/staff/private data. Distinguish validated shape from authorization and state validity. Stale report transitions reject safely; retries cannot duplicate canonical reports, recognition or remittance releases. Exact idempotency/version transport is a contract-review choice, not an invented public header or extra business action.
