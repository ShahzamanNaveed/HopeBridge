# Security foundation and planned controls

Implemented: Helmet headers, generated request IDs, bounded JSON parsing, environment validation, database connection/query timeouts, API rate limiting and safe error responses. Logs omit query strings, request bodies and incoming credentials; Pino redaction covers cookie, authorization, set-cookie and common secret fields. Avoid logging personal data in future modules.

Planned before authenticated endpoints: Argon2id password hashes; opaque server-managed sessions persisted in PostgreSQL; Secure, HttpOnly, SameSite cookies in production; session rotation on login/privilege changes, expiry, logout/revocation and login throttling. Do not store bearer tokens in browser local storage. These are architectural requirements, not implemented security features.

CSRF design: validate trusted Origin on state-changing requests and a server-bound synchronizer token; SameSite cookies are defense in depth. Reject unsafe requests before controllers. AUTH-003 fixes session lifetime; cookie name, synchronizer-token delivery and exact deployment origin/topology configuration remain technical choices. AUTH-005 mandates CSRF controls; SameSite alone never replaces them. Add adversarial tests before exposing mutations.

Authorization design: deny by default, centralized permission policies, server-derived branch context and scoped repository queries. Test each role and cross-branch access. No public shell route implies permission to business data. Database credentials and session secrets belong in deployment secret storage. TLS terminates at the deployment platform.

## AUTH-001 to AUTH-006 - DECIDED HWF policies

These approved HWF policies refine SA-001 to SA-008 and the existing Argon2id/PostgreSQL-session design. They are requirements, not implemented controls or independently verified extra handbook mandates. Exactly five authenticated roles remain; Public Visitor is anonymous and members have no automatic staff account.

- **AUTH-001 - DECIDED:** Super Admin provisions staff. Generate cryptographically secure random temporary password; persist only its secure hash, never plaintext/reversible encryption. Server issuance time sets expiry exactly +24 hours; authentication fails at/after expiry. Mark mandatory password change. Successful temporary login creates only a restricted session permitting minimum password replacement and session termination, never ordinary protected work. After successful creation/reset commit, show plaintext only once to authorized Super Admin in an authenticated protected response, with a secure opportunity to capture it. No later list/detail/retrieval, URL/history/persistent-client-storage exposure, logs/audit/analytics/exception traces or notification emails. No automatic plaintext credential emails. Lost disclosure requires a fresh authorized reset, not retrieval.
- **AUTH-002 - DECIDED:** Only authorized Super Admin initiates existing-staff reset after target existence/allowed-state checks. In one transaction replace hash with a newly generated temporary credential, server issuance/+24h expiry and mandatory-change state, revoke all target active sessions and append sanitized audit. Recheck authorization/account restrictions and SA-008 protection; reset never bypasses inactive status or assignment prerequisites. Show new plaintext once only after commit under AUTH-001; never expose old passwords. No public self-reset/email-based recovery without separate approval. Failure rolls back persistent account/session/audit changes.
- **AUTH-003 - DECIDED:** Opaque server-managed revocable sessions, persisted in PostgreSQL under the existing design. Login creates a new tracked session. Maximum inactivity 8 hours, absolute lifetime 24 hours from issuance; deny at/after whichever deadline is earlier. Only an authorized request may refresh idle deadline, never original absolute deadline or already expired/revoked session. Use authoritative server time and concurrency-safe handling. Logout revokes active session. Password change must securely rotate/invalidate credentials/sessions; reset revokes all old target sessions. Revalidate current role, assigned branch and active status on every protected request; stale client claims never preserve authority. No non-revocable client-only JWT design.
- **AUTH-004 - DECIDED:** Authorized Super Admin deactivation updates status and immediately revokes all target sessions consistently with sanitized audit; block new login and protected requests using old cookie/session. Enforce last-active-Super-Admin and Branch Lead replacement prerequisites atomically. Keep staff identity and historical audit attribution; no physical historical identity/audit deletion. Reactivation restores no old session and uses a secure authorized credential procedure, never silently reviving expired temporary credentials.
- **AUTH-005 - DECIDED:** Opaque session ID in HttpOnly cookie, Secure in production, topology-appropriate SameSite and restrictive path/domain. No authentication secrets in localStorage or logged session IDs. Secure rotation/invalidation, backend authorization on every protected endpoint and deny by default. CSRF synchronizer token plus trusted Origin validation for authenticated unsafe requests; SameSite is defense in depth. Apply login rate limiting, generic authentication failures, appropriate origin checks and secure CORS for actual deployment. Verify password using approved Argon2id hash design, not plaintext comparison. Creation/reset one-time responses must prevent caching and accidental secret logging. Thresholds/topology configuration remain pending, not the controls.
- **AUTH-006 - DECIDED:** Preserve SA-003/SA-004 constraints: at most one branch per lead and one assigned active lead per branch; Active branch must retain eligible accountable leadership during atomic replacement. Validate candidate/account/assignment prerequisites, replace and record actor/old-new assignments in append-only audit together. Immediately invalidate outgoing former-branch authority via affected-session revocation or equally immediate server-enforced invalidation, including existing cookies/caches. No automatic access to another branch; a still-active outgoing account has only independently authorized current role/assignment permissions. Related deactivation follows AUTH-004; failure preserves old lead/access and all history.

## Future acceptance criteria (not executed tests)

- Temporary credentials work strictly before issuance +24h and fail exactly at/after expiry using server time. Valid temporary login cannot use ordinary protected endpoints; only password replacement/logout is available until successful change.
- Creation/reset plaintext is shown once only in protected noncacheable response, never retrievable through later reads or leaked in URL/storage/log/audit/analytics/errors/email. Lost password requires fresh reset; old hash/credential no longer authenticates after reset.
- Reset atomically revokes every old target session with hash/control/audit changes; failed writes roll back. Unauthorized roles/public direct requests cannot provision/reset/deactivate/assign.
- Deactivated staff cannot login or use issued sessions; reactivation restores neither sessions nor expired temporary credentials. Preserve identity/audit and replacement prerequisites.
- Idle session denies at 8 hours; absolute denies at 24 hours despite authorized activity. Unauthorized requests do not refresh idle timeout. Logout invalidates session; concurrent refresh cannot resurrect expired/revoked sessions or extend absolute lifetime.
- Missing/invalid CSRF token and untrusted Origin reject authenticated state-changing browser requests; unauthenticated/expired/revoked and forbidden-role/branch requests fail server-side.
- Outgoing Branch Lead loses former-branch access immediately with existing session; Active branch never becomes leaderless. No new branch granted automatically.
- Concurrent last-admin deactivation/demotion cannot remove final active Super Admin; audit includes no plaintext password/session identifier. These are future synthetic-data tests, not passing evidence.

## CMS-005/CMS-007 - DECIDED planned safety boundaries

CMS controls are not implemented. Server-side sanitize all publishable rich text; reject or sanitize unsafe HTML, scripts, event-handler attributes and dangerous URLs before public or staff-preview rendering to prevent stored XSS. Backend-authorize private Preview and upload/edit; preview grants no Publish bypass. Validate safe image formats against metadata AND actual content, configured size limits and safe storage identifiers; never trust filenames/MIME alone or expose filesystem paths. Keep safe media references across revisions.

Public APIs serve sanitized actively published fields only, not Draft/preview/history/private metadata. Archive/Unpublish immediately excludes lists and detail/direct-ID endpoints; cache coordination prevents newly fetched retired content appearing live. CMS-003 fixed routes retain safe fallback, never Draft fallback. CMS-004 publication eligibility and atomic pointer/audit checks preserve complete bilingual revisions; CMS-006 uses server time, not browser claims, and dates never override hidden status. Existing CE authority/five roles unchanged. Exact safe-format allowlist, size limits, vendor, transformation pipeline and editor/sanitizer library remain PENDING technical choices; no specific provider required. ## PERM-001 to PERM-005 / EXP-001 to EXP-004 - DECIDED planned controls

Backend authorizes active sessions and role/domain/current-assignment scope on every audit/export request, including direct IDs/URLs and filters; deny invalid/expired sessions, unrelated domains and cross-branch requests. AUTH-006 immediately removes former-branch access. Super Admin audit oversight is sanitized, not unrestricted secrets/write access. No application role updates/deletes audit; never expose credentials, session tokens, private keys or sensitive authentication artifacts. Minimize personal data and preserve transactional mutation audit with actor/system/action/time/record/before-after/context. System process is not an extra login role.

Financial CSV/PDF grants and fields follow [PERM/EXP permissions](permissions.md): organization-wide authorized Super Admin/Finance, current-branch Branch Lead only; HR/Content Editor/Public denied. Same server authorization/filters/effective revision/exact totals in both formats. Server-side formula-injection protection handles untrusted spreadsheet text beginning =,+,-,@ with correct CSV delimiter/quote/line-ending encoding; preserve legitimate negative numeric money semantics. Escape/sanitize untrusted PDF text and exclude hidden staff/unrelated applicant/member data. Responses protected against unintended caching/public access; URLs are not authorization bypasses. Successful export append-only audit contains sanitized actor/action/time/scope/filters/format/source IDs, never unnecessary sensitive file content/secrets; denied requests may be separately security-logged, never labelled successful exports. Monitoring, retention/redaction configuration and export libraries/streaming remain pending, not these controls.
