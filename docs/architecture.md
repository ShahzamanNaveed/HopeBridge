# Architecture

Current A-02 addition (2026-10-29): real auth repository/service/router, PostgreSQL sessions, transactional permission ports and EN/UR React authentication are implemented/tested locally on the existing DB-01 models. [Authentication implementation and consumer contract](authentication.md) supersedes earlier statements below that auth/client mutations were still only planned; other domain implementations and B consumer acceptance remain pending.

Accepted: modular monolith using npm workspaces. React/Vite in apps/frontend communicates with versioned Express HTTP endpoints in apps/backend. Both consume packages/contracts. PostgreSQL is the source of truth, accessed through Prisma and its PostgreSQL driver adapter. Production Express serves frontend assets on the same origin; Vite proxies requests during development.

Frontend features own domain UI; shared components own reusable primitives; layouts own navigation. Backend modules will own routes/controllers, services/policies and repositories. Infrastructure supplies database connectivity and observability plus technical adapters for sessions/export rendering/audit persistence; domain services below own their policies and orchestration. Do not duplicate business rules in the browser.

DB-01 now defines the initial shared business schema plus unchanged foundation_markers; see [implemented models/SQL contracts](database.md). No official financial fixtures or staff credentials are seeded. Health runs SELECT 1 and returns 503 if PostgreSQL cannot be queried.

Initial physical models/migrations and shared audit writer are implemented/tested locally under DB-01; domain services remain to implement. AUTH, action-level permissions and financial policies are approved documentation; their implementation and remaining specific decisions belong to the next milestone. See [ADR 0001](adr/0001-foundation.md), [permissions](permissions.md) and [remaining clarifications](requirements/clarifications.md).

## Pre-development integration baseline (2026-10-28; documentation only)

Keep HopeBridge and @shiplens/frontend, @shiplens/backend, @shiplens/contracts names. Existing frontend router has seven public shells plus a public /dashboard preview; no business RBAC/session/CMS/report endpoint exists. Shared code currently defines pagination, errors and health only; Prisma defines 33 mapped models and 21 enums, including FoundationMarker. React 19/Vite/TypeScript and Express 5/TypeScript/PostgreSQL/Prisma remain the stack. No new business module is needed to organize contracts.

Controllers parse transport/call services/map DTOs; services/domain policies enforce business state, repositories own database access. Do not import another module's repository. Cross-module services expose explicit narrow application ports rather than repository/ORM objects or transport handlers. Shared infrastructure cannot become a second financial or audit implementation.

### Transaction-safe integration contracts

These are logical interfaces to implement/review together, not existing method signatures or finalized physical models. The operation's initiating application service owns a single transaction boundary. Participating module ports receive the same explicit backend transaction capability and authorized context; they do not independently commit or open isolated transactions. Audit appends use that capability. A failing invariant, constraint, business write, audit write or commit rolls back the entire operation; external email/delivery happens after commit and cannot reverse HR decisions.

| Coordinator / contract              | Required inputs and checks                                                                                                                                                | Consistent result                                                                                                                                                                                                                                                         |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| users staff mutation                | Current actor/action, target version/state/role; auth credential/session controls; branches replacement and last-admin safeguards                                         | Account/credential/assignment changes, immediate required revocation and sanitized audit together; one-time credential disclosure only after commit                                                                                                                       |
| applications HR decision -> members | Application/link/state, self-excluded contact checks, branch ID/current authoritative city/Active eligibility, member status/current assignments                          | First acceptance/member/city ID/link/audit once; reversal inactivates retained member/ends active assignments; reacceptance same ID without reopening assignments                                                                                                         |
| members transfer                    | Scoped source request, current member/branch, different Active target and HR decision                                                                                     | Approved current-branch update/audit preserves identity/historical attribution; unresolved consent/finance paths remain gated                                                                                                                                             |
| collections <-> reports             | Current branch/report interval/state/revision, eligible original occurrence/created_at, exact originals/recognized adjustments/Late Entry/reservations/confirmed measures | Reports returns eligibility for inclusion/edit; collections allocates recognition once and returns canonical projection/source references. Generation/recognition/transition use same transaction/version protection; no duplicate recognition or frozen-snapshot rewrite |
| collections remittance              | Current branch/role, pending reservation/cancellation/confirmation state and exact balance                                                                                | Reserve/confirm/release at most once under approved Finance/Branch Lead separation with audit                                                                                                                                                                             |
| content publication/retirement      | Item/revision/current visibility, mandatory bilingual/safety/version and route checks                                                                                     | Atomic publication pointer/audit and immutable history; retirement/public cache coordination honors immediate visibility guarantee                                                                                                                                        |
| dashboard export                    | Server-authorized scope/filters, effective report revision/snapshot and canonical financial measures                                                                      | CSV/PDF same selection/exact totals, safe/private output and successful-export audit metadata; no monetary mutation                                                                                                                                                       |

Collections owns calculations/recognition records; reports owns report eligibility, membership of lines and frozen/final evidence. Neither recomputes incompatible accounting definitions. Establish source/revision identifiers and locking/order strategy in the schema/contract review; use database constraints and concurrency-safe retries only where safe. Read projections may compose module service DTOs; no cross-domain raw repository imports. Unresolved paths in [clarifications](requirements/clarifications.md) stay denied/gated, without blocking unrelated approved work.

### Shared contracts and frontend integration

packages/contracts is the shared Zod transport schema/type source, not a domain service or Prisma export. Define params/query/body/response/error shapes per [API contract categories](api.md); frontend and backend use compatible schemas, server still rechecks authorization and domain invariants. No database clients/backend secrets in frontend/contracts, no incompatible duplicate form schemas. Financial values are decimal strings; timestamps unambiguous UTC/offset, Asia/Karachi for business interpretation.

Frontend features use the central apps/frontend/src/services/api-client.ts and TanStack Query for server state, React Hook Form/shared Zod for forms, existing i18next en/ur resources for labels/stable error-code messages, and functional LTR/RTL throughout forms/tables/feedback. Current client only implements GET/envelope extraction and string Error messages: authenticated mutations, CSRF, typed field-error handling, runtime business response validation and protected downloads are future extensions to that same client, not existing features. Maintain session/branch-scoped query keys and discard stale protected state after logout/role/assignment changes; backend remains authoritative. Protected unsafe requests need AUTH CSRF/Origin/session controls; anonymous intake follows APP consent/rate/honeypot rules. Language switches preserve application values AND validation state without submission or URL/analytics disclosure.
