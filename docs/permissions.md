# Permission matrix - approved actions and remaining decisions

## Official Requirements

Exactly five authenticated roles with server-enforced permissions and branch isolation.

## Confirmed HWF Decisions

| Role             | Primary responsibility                                         |
| ---------------- | -------------------------------------------------------------- |
| Super Admin      | Users, branches and overall administration                     |
| Finance Reviewer | Approve/return weekly reports and monitor unsent collections   |
| Content Editor   | Manage and publish public website content                      |
| Branch Lead      | Manage assigned branch members, collections and weekly reports |
| HR Lead          | Review and accept/decline volunteer applications               |

No separate Head Office Admin role. HR operations are centralized at Head Office initially. Volunteers are member records, not another login role; public visitors need no authentication. Staff accounts are provisioned through an authorized administrative process.

## DECIDED authentication authority and session boundaries

- **AUTH-001/AUTH-002 - DECIDED:** Only backend-authorized Super Admin provisions/resets allowed existing staff targets and receives the one-time protected post-commit temporary password response. Other roles and public users have no account provisioning/reset grant; no public/email recovery. Hash only, exact server-issued +24h temporary expiry, mandatory-change state, no later secret retrieval/logs/audit/email/storage. Reset revokes all target sessions with account controls/sanitized audit atomically; inactive/last-admin restrictions remain.
- **AUTH-003/AUTH-005 - DECIDED:** Every staff role uses revocable server sessions with 8h maximum idle/24h absolute earliest expiry, authorized-only idle refresh and logout revocation. Temporary-login session has minimum password replacement/termination authority only, no ordinary role work. After secure password change/rotation, ordinary actions still require current role/assignment/active status. Opaque HttpOnly cookie, Secure production, topology-appropriate scope/SameSite, no localStorage secrets/logged session IDs, CSRF plus Origin/CORS controls and throttled generic login failures apply to all roles. See [security](security.md); thresholds/configuration pending, authority/lifetimes decided.
- **AUTH-004 - DECIDED:** Only authorized Super Admin deactivates/reactivates accounts under safeguards. Deactivation immediately revokes all target sessions and blocks old protected requests/new login with consistent status/audit, retaining identity/history; last active admin cannot be removed and assigned lead needs valid replacement. Activation restores no prior sessions/expired temporary credential and requires secure authorized credentials.
- **AUTH-006 - DECIDED:** Super Admin-only replacement atomically preserves eligible Active-branch leadership, assignment/account prerequisites and old/new actor audit; revoke affected sessions or equally immediately deny outgoing former-branch scope server-side. No automatic new branch or multi-branch authority; remaining access follows independently authorized current role/assignment. Existing financial, HR and CMS separation is unchanged.

## WR-001 to WR-006 system and report authority (DECIDED)

- **WR-001/WR-002/WR-005 - DECIDED:** Automatic generation/recovery is a system process, not an additional human staff role or Branch Lead dashboard action. Only eligible Active/Paused operational branch/week Drafts, including zero activity, are generated with system audit and canonical uniqueness; no Head Office operational report. FIN-014 ordinary future-week Closed reports prohibited; legitimate pre-closure recognition container/period remains PENDING.
- **WR-003/WR-006 - DECIDED:** Branch Lead may retrieve/review/submit/resubmit only their assigned branch within valid state/version; no Finance Return/approval. Finance Reviewer may view/review/Return with reason or approve authorized Submitted reports, with atomic approval/lock. Preserve frozen submitted revisions/Approved snapshots, backend authorization/current branch checks, append-only audit and concurrency-safe transitions. No manual lock or Approved reopening grant, no other staff-role grant.
- **WR-004 - DECIDED:** Finance approval requires transactional relevance checks for unresolved issues that could materially affect the candidate's eligible figures; unrelated branch/period or non-affecting request does not automatically block. Denial leaves report state unchanged; resolution triggers reassessment. Unapproved amounts never recognized. Exact multi-period dependency treatment remains implementation-level specification, not global blocking.

## DECIDED financial operation boundaries

- FIN-006: Branch Lead may request an eligible expired/immutable own-branch collection adjustment with signed amount/explanation; Finance Reviewer approves/rejects once. Only Approved recognition affects totals. No Finance self-proposal grant or Branch Lead approval grant.
- FIN-007/FIN-009: Branch Lead records partial remittances with required positive exact amount, valid transfer date, nonempty reference and backend-derived branch; optional evidence upload is not mandatory. Validate available balance/reservations. Branch Lead cannot Finance-confirm; Finance Reviewer independently confirms once within authorized central finance scope.
- FIN-008/FIN-004: Finance Reviewer returns Submitted only with trimmed nonempty reason, or approves and final-locks atomically. Branch Lead never self-approves.
- FIN-005 recognition follows approved report scope and immutable-history constraints; it grants no cross-branch mutation or manual override.
- Backend authenticates active staff and enforces current record ownership, branch scope, state/amount/concurrency checks on every operation. Finance scope across permitted branches gives no member/CMS permission or silent source-collection edit authority. Other role grants remain pending; all five official roles are retained.

- **FIN-010 - DECIDED:** All financial actions validate PKR Decimal/NUMERIC(18,2) and decimal-string money with at most two fractional digits; no JS number money arithmetic or silent excess-precision rounding. HALF_UP applies only where calculation requires rounding.
- **FIN-011 - DECIDED:** Approved correction may expose negative signedOutstanding and reconciliationDeficit to authorized Finance/Head Office users; availableToRemit remains nonnegative after reservations. This grants no automatic payment/write-off or historical rewrite; external clearing/recovery authority remains PENDING.
- **FIN-012 - DECIDED:** Current own-branch Branch Lead requests Pending remittance cancellation; cannot finalize or directly cancel Confirmed. Finance Reviewer alone approves/rejects valid requests in scope. Request/rejection preserves claim and original Pending remittance; approval atomically cancels to non-reserving state, releases once and audits. Confirmation/cancellation race has one valid outcome; no confirmed-history erasure/reversal grant. Super Admin, HR Lead, Content Editor and Public Visitor have no cancellation grant through these policies.
- **FIN-013 - DECIDED:** Branch Lead may make sequential original-linked adjustment requests after prior PendingReview closes; at most one PendingReview per original. Finance decides each, rechecking cumulative Approved corrected value including queued approvals cannot be negative. Only Approved recognized once; no Finance proposal or Branch Lead approval authority added.

- **FIN-014 - DECIDED:** Existing grants do not permit ordinary Closed-branch collections/future-week reports, reactivation or grants to deactivated/unassigned leads. Legitimate pre-closure reconciliation needs current authorized Finance scope/role separation and separate audit; exact recognition container/period and manual external settlement authority remain PENDING, no new broad settlement grant.
- **FIN-015 - DECIDED:** Finance alone rechecks relevant approval dependencies under WR-004 by candidate branch/report/recognition scope; no blanket submission ban or automatic adjustment approval.
- **FIN-016 - DECIDED:** Same-branch cumulative deficit offset is automatic exact accounting calculation, not new payment/manual-write-off authority or cross-branch financial transfer. Preserve historical records and deficit-aware authorization/balances.
- **FIN-017 - DECIDED:** Branch Lead records own-branch remittance against branch-level availability; Finance confirms valid Pending independently. No mandatory per-collection allocation grant/requirement; reservation, partials, confirmation/cancellation separation and audit unchanged.
- **FIN-018 - DECIDED:** Branch Lead adjustment request needs nonempty reason, file optional; Finance decides under existing FIN-006. Missing file alone cannot deny valid request; attachment never substitutes for reason/permission/correctness. Remittance file optional, amount/date/reference required; controlled evidence access grants no unrelated HR/CMS/branch power.

## DECIDED CMS operation boundaries

- **CE-001 - DECIDED:** Active authenticated Content Editor may create/edit authorized Drafts, Preview, Publish, Unpublish and Archive public CMS content. Normal publication requires no Super Admin approval and introduces no Publisher role. Existing Super Admin oversight is unchanged; other staff roles do not automatically inherit Content Editor grants.
- **CE-002/CE-003 - DECIDED:** Publish requires complete required en/ur content (English LTR, Urdu RTL); incomplete Drafts allowed. Published edits create a new Draft while old published revision remains live until atomic revision-pointer publication/audit; preserve history.
- **CE-004/CE-005 - DECIDED:** Published events automatically classify as Past at event-period end, without automatic archive/unpublish/delete. Normal retirement uses Archive/Unpublish, preserving item identity/revisions/audit instead of hard deletion.
- Backend authorizes CMS item/action and protected Draft/Preview access on every request. Public visitors need no authentication to read actively published content, but cannot access Draft/internal preview, archived/unpublished or private historical revisions as current content.
- CMS grants no staff management/Branch Lead assignment, operational branch lifecycle, HR decision, collection/report/remittance or unrelated restricted internal audit permission. Required public routes and account-free volunteer application remain intact.

### CMS-001 to CMS-007 - DECIDED refinements

Existing CE-001 to CE-005 grants/oversight unchanged: Content Editor alone under existing CMS permissions performs authorized Draft/Edit/Preview/Publish/Archive/Unpublish; no mandatory Super Admin publication approval or sixth Publisher role, no automatic grants to other roles. Backend authorizes staff upload/edit and private preview; preview cannot bypass publication. CMS-004 requires complete mandatory bilingual fields before Publish, while incomplete Drafts remain permitted. CMS-003 protects seven mandatory routes from slug edits/retirement. CMS-005/CMS-007 restrict anonymous reads to sanitized actively published content, denying Draft/private preview/history and retired items even through direct IDs; retired list/detail visibility ends immediately with cache coordination. CMS-006 Past classification grants no new permission and never exposes hidden events. CMS schemas/timing: [content contract](../project-context/modules/content-management.md). No HR, operational branch, financial or unrelated restricted audit grant added.

## PERM-001 to PERM-005 - DECIDED audit and read scopes

These are approved HWF requirements, not implemented permissions. All reads authenticate active staff, enforce current role/record scope server-side, minimize personal data and redact secrets. Read/export never grants business writes or overrides immutable Approved figures.

- **PERM-001 - DECIDED:** Super Admin views organization-wide sanitized audit history. No application role, including Super Admin, may update/delete audit entries or expose credentials, session tokens, private keys or sensitive authentication artifacts. Oversight does not grant unrelated business mutations.
- **PERM-002 - DECIDED:** Finance Reviewer views organization-wide weekly financial reports/preserved revisions, review-relevant offline collections, adjustments/decisions, remittances/reservation/cancellation/confirmation states, Approved figures/reconciliation deficits and related financial audit. Exclude unrelated HR notes, password events and CMS administration. Creation remains Branch Lead's approved responsibility; Finance review is not source-edit or Approved-report-edit authority.
- **PERM-003 - DECIDED:** Branch Lead views approved member operations, collections, weekly reports/submission history, adjustment/remittance workflow history and related audit for CURRENT assigned branch only. Derive scope from backend assignment, deny guessed cross-branch IDs/filters and immediately revoke former-branch scope under AUTH-006. No organization-wide audit, unrelated HR decisions or staff security records; transfer history must not leak another branch's private data.
- **PERM-004 - DECIDED:** HR Lead views authorized organization-wide applications, decisions/reversals, member identity/status/assignment histories, transfer requests/HR decisions and HR audit. Omit unnecessary collection amounts, remittance evidence, adjustment details and all authentication secrets while preserving internal financial history. No Finance approval authority.
- **PERM-005 - DECIDED:** Content Editor views authorized CMS Drafts, published/historical revisions, preview/publication status, archive/unpublish history and related CMS audit only. No unrelated applications/HR/finance/staff security audit. CE-001 to CE-005 and CMS-001 to CMS-007 publishing authority remains, without mandatory Super Admin approval.

## EXP-001 to EXP-004 - DECIDED financial exports

- **EXP-001 - DECIDED:** Financial CSV and PDF: Super Admin and Finance Reviewer may export authorized organization-wide reports; Branch Lead only authorized reports of current assigned branch. HR Lead, Content Editor and anonymous Public Visitor denied. Backend authorizes every request/direct report ID/export URL; supplied branch parameters never expand scope. This is financial report export, not an audit-file export grant.
- **EXP-002 - DECIDED:** Validate/enforce authorized server selections for reporting period, branch, report status, financial totals, Approved/pending classification, recognized adjustments and pending remittance reservations where relevant, confirmed remittances, signed outstanding, reconciliation deficit and available-to-remit. Use FIN-010 exact PKR Decimal and FIN-001 to FIN-018 accounting. Label live Draft estimates, frozen Submitted revisions and immutable Approved snapshots distinctly; keep outstanding/reserved/confirmed separate. Lifetime/cumulative and period figures are not interchangeable; official KPIs/fixture totals remain unavailable. Exact column names/order and PDF layout remain implementation contracts.
- **EXP-003 - DECIDED:** CSV/PDF for the same authorized selection share authorization, server filters, effective report revision/snapshot, exact aggregation and reconciled PKR totals; no independent client calculation. Server-side CSV formula-injection protection for spreadsheet-interpretable untrusted text beginning with =, +, - or @, plus correct delimiter/quote/line-ending encoding. Preserve legitimate signed monetary values as numbers rather than treating them as malicious text. Escape/sanitize PDF display text and omit hidden staff data.
- **EXP-004 - DECIDED:** Each successful export appends audit actor, action/export type, timestamp, effective branch scope, applied filters, format and source report/revision identifiers where available. No unnecessary file contents/secrets/private application/member data. Deny unauthorized direct calls; denied security logging is separate, never a successful-export event. Protect responses against unintended caching/public access.

### Shared audit invariants

Audited business mutations commit actor/system identity, action, timestamp, affected entity/record, before/after values and appropriate branch/context identifiers transactionally with the mutation, sanitizing secrets. No application role updates/deletes history. System report generation uses a system actor, not a fabricated human/sixth login role. Exports append audit without changing financial records/snapshots; ordinary viewing is not an invented business mutation. Audit-file export authority is not established by financial EXP grants.

Full financial semantics: [domain rules](domain-rules.md). Planned denial/export coverage: [dashboard acceptance scenarios](../project-context/modules/dashboard.md). Exact audit pagination/filter contracts, retention/redaction configuration, monitoring, generation libraries, column order/PDF layout/file naming and large-export streaming/batching remain PENDING; approved role scopes do not.
