Resolved financial policies (DECIDED; see [domain rules](../domain-rules.md), [collections](../../project-context/modules/collections.md), [weekly reports](../../project-context/modules/weekly-reports.md) and [financial permissions](../permissions.md)):

- **BL-001/BL-002:** Authoritative server-created `created_at` plus seven elapsed days is the normal edit cutoff; at/after cutoff rejected, edits never reset it. Submitted collections locked until formal Return; Returned corrections still require original window; Approved/immutable snapshot inclusion permanently locked. Backend enforces scope/time/state together.
- **BL-003/FIN-001:** Asia/Karachi Monday 00:00 inclusive to following Monday 00:00 exclusive, one canonical branch/week report. Original attribution uses actual collection occurrence, not creation/edit time; exact money only.
- **FIN-002/FIN-005/FIN-006:** Expired originals/history remain unchanged; source Branch Lead requests a separate signed next-eligible-report adjustment, Finance Reviewer approves/rejects, only Approved recognized once. Locked-original-week late collections instead retain actual date/week and use a distinct original-linked Late Entry once in earliest subsequent same-branch eligible report, never Submitted/Approved; queue if none. No historical snapshot rewrite, duplicate recognition or automatic negative late-entry adjustment.
- **FIN-003/FIN-007/FIN-009:** Branch Lead records own-branch partial remittances; Finance Reviewer independently confirms once. Required positive exact amount, valid transfer date and trimmed nonempty reference; upload optional. Prevent over-remittance concurrency-safely using pending reservations; outstanding is recognized net less confirmed (subject to adjustment reconciliation), FIN-011 availableToRemit is max(0, signedOutstanding less committed pending claims); signedOutstanding can be negative and exposes reconciliationDeficit separately. Unconfirmed is not confirmed receipt.
- **FIN-004/FIN-008:** Finance approval atomically locks snapshot and saves approval/lock metadata/audit; no separate manual lock. Return only from Submitted requires backend-validated meaningful nonempty trimmed reason and audited feedback, never resetting collection cutoff. Approved cannot be returned normally.

- **FIN-010 - DECIDED:** PKR NUMERIC(18,2)/Prisma Decimal, decimal-string APIs, at most two fractional digits, reject nonfinite/unsupported precision/range and float-derived money; no JS number money arithmetic or silent direct-record rounding. Explicit HALF_UP only where calculation needs rounding; same exact model for aggregates/snapshots/dashboard/exports.
- **FIN-011 - DECIDED:** Preserve locked originals, confirmed remittances, Approved snapshots/adjustment history and occurrence/recognition attribution. netRecognizedCollections minus confirmedRemittances = signedOutstanding, possibly negative; reconciliationDeficit is max(0, -signedOutstanding), availableToRemit is max(0, signedOutstanding - active pending reservations), without double deficit deduction. Expose deficit to authorized Finance/Head Office; require audited reconciliation and sufficient remittance coverage, never automatic payment/write-off.
- **FIN-012 - DECIDED:** Own-branch Branch Lead requests Pending cancellation; Finance alone approves/rejects. Request does not release; rejection retains original Pending/claim. Approval atomically cancels non-reserving, releases once and audits; confirmation/cancellation race has one valid result. Confirmed history unchanged, no confirmed reversal endpoint.
- **FIN-013 - DECIDED:** Sequential requests allowed, one PendingReview per original at a time; Finance decides each with immutable unique reference/request/decision/audit. Preserve previous approvals/original; recognize each Approved once in eligible period, Rejected zero effect. Approval rechecks original plus all Approved deltas (including queued approvals) plus candidate >= zero. See [authoritative financial measures and exceptions](../domain-rules.md).
