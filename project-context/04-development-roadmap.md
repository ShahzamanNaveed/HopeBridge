# Proposed 14-day roadmap

Day 1: repository foundation and verification. Day 2: handbook review, complete domain design, permission matrix, workflow specifications. Day 3: database migrations and shared contracts. Day 4: sessions, Argon2id authentication and CSRF. Day 5: authorization and branch scoping tests. Day 6: branch lifecycle. Day 7: volunteer applications and HR approvals. Day 8: member management. Day 9: offline collections and financial invariants. Day 10: weekly reporting and audited transitions. Day 11: sample-data dashboard reconciliation. Day 12: content draft/publish and public pages. Day 13: localization/accessibility, regression and security tests. Day 14: Render acceptance, CI evidence and handover.

This is a proposed sequence, not a completed schedule. Schema implements approved HWF policies and documented provisional ShipLens scope; already decided permissions are not awaiting blanket reapproval. Specific unresolved business paths remain gated; authoritative dashboard acceptance depends on missing official fixtures/handbook. Deployment preparation should begin early once hosting credentials are available.

## Proposed two-developer integration plan (unassigned)

Owner confirmation is required before assigning people; this is a dependency-aware proposal, not a claim of work started/completed or approval to implement in this documentation task. Approved [freeze baseline](03-current-state.md) supports staged implementation of decided core behavior while [affected pending paths](../docs/requirements/clarifications.md) stay gated. Library selection alone is not a reason to block unrelated core modules.

### Required dependency handoffs

1. **Baseline and ownership review:** Confirm people, domain contract owners and one schema/migration owner at a time. Review [module ports](../docs/architecture.md), conceptual constraints/transactions and remaining business gates. Coordinate central schema.prisma, router and shared middleware edits rather than editing simultaneously.
2. **Shared contracts review:** Producer/consumer agree params/query/body/DTOs, stable errors/field feedback, session/CSRF, money/time/version semantics. Each domain owns its @shiplens/contracts category; record deliberate compatible changes in existing context. No consumer builds against privately changed API assumptions.
3. **Protected foundation handoff:** A provides reviewed auth/current-role/branch policy and ONE transaction-aware audit writer. Verify denial/current-branch/session revocation with integration tests before sensitive endpoints depend on them. B may develop approved public presentation while those dependencies are prepared, clearly distinguishing mock UI from integrated behavior.
4. **Identity/public-content handoff:** Agree branch/public projections, APP consent/contact rules, atomic HR/member ports and immutable IDs. B integrates forms/CMS against those contracts; content service/schema changes go through the shared schema owner. Unresolved member/transfer/consent-copy paths are not silently implemented.
5. **Financial contract gate:** A/B review collections recognition/Decimal measures, report eligibility/version/frozen snapshots and exported selection semantics before parallel finance/report work. Database uniqueness/transaction/lock strategy reviewed together; B displays server projections instead of a second client accounting engine.
6. **Integrated verification and release handoff:** Execute domain unit/HTTP plus real PostgreSQL transaction/concurrency/role-denial suites, full bilingual RTL E2E, CSV/PDF reconciliation and safe-output tests. Obtain official fixtures/handbook for exact KPI/four-gate assertions. Then verify current CI, Docker/runtime/health, Render and submission evidence; earlier foundation CI is not current acceptance.

Shared interface changes require consuming-owner review and affected-module impact assessment before code merges. Feature branches/reviewed PRs require owner authorization under repository rules; no commits/branches/PRs/deployment are created by this plan. Revisit the proposed day sequence against actual dependencies, owner decisions and official evidence; do not mark days delivered merely because documentation exists.
